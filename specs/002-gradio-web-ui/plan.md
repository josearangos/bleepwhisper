# Implementation Plan: Bleeper Web UI — Background Masking Jobs in the Browser

**Branch**: `002-gradio-web-ui` | **Date**: 2026-10-26 | **Spec**: [spec.md](spec.md)

**Input**: Feature specification from `/specs/002-gradio-web-ui/spec.md`

## Summary

A local Gradio 6 app (`bleeper-ui` / `python -m bleeper.ui`, bound to `127.0.0.1`) with a form
(audio, language, words file, preset with previews or custom mask) that validates synchronously
and enqueues a job. A single daemon worker thread runs jobs FIFO by calling the unchanged
`bleeper.core.process_audio` with the CLI's defaults and one shared transcriber (the model is cached
by the core), so the output is byte-identical to the CLI's. Jobs live in a thread-safe in-memory
store mirrored atomically to `jobs.json`; restart recovery marks interrupted jobs as failed. The page
shows a jobs table refreshed every 2 s and a job details panel (player, downloads, delete) that
re-renders only when the selected job changes status. The core gains three small additive helpers
(`probe_audio`, `preset_preview`, and a `load_words` re-export), so the UI has no audio logic. See
[research.md](research.md).

## Technical Context

**Language/Version**: Python ≥ 3.10 (local venv: 3.12)

**Primary Dependencies**: Existing core (faster-whisper, numpy, soundfile ≥ 0.12.1, ffmpeg);
new optional extra `ui = ["gradio>=6,<7"]` (6.30.0 current); dev: pytest, ruff, gradio

**Storage**: Local files: `<data-dir>/jobs.json` plus `<data-dir>/jobs/<id>/` (default
`~/.bleeper/ui`)

**Testing**: pytest; fake transcriber and synthetic audio from `tests/conftest.py`; Gradio handlers
called directly; `build_app()` smoke test; no model or network

**Target Platform**: macOS / Linux desktop, local browser, CPU only

**Project Type**: Single Python package. The library core and CLI already exist; this adds the
`bleeper.ui` subpackage

**Performance Goals**: Submit returns < 1 s (SC-001); table reflects changes within 2 s (SC-006);
job processing time equals the CLI's (1 min audio < 1 min on the reference machine), with no model
reload after the first job (SC-007)

**Constraints**: Local-only bind; offline (no analytics, no web fonts); no audio logic outside
`bleeper.core`; Gradio's cache kept inside the data dir; uploads and temp input copies always
removed; no transcript logging; ≤ 100 MB and ≤ 30 min per
upload

**Scale/Scope**: One local user; tens of jobs per session; four small UI modules plus three core
helpers; built in about 2 h

### Source Code (repository root)

```text
pyproject.toml               # + ui extra (gradio), gradio in dev, bleeper-ui script, soundfile>=0.12.1
src/bleeper/
├── cli.py                   # unchanged
├── core/
│   ├── __init__.py          # + re-export probe_audio, AudioInfo, load_words, preset_preview
│   ├── audio_io.py          # + AudioInfo, probe_audio()          (header read only)
│   └── presets.py           # + preset_preview()                  (pure; uses masking.fade)
└── ui/
    ├── __init__.py          # package docstring only (no Gradio import)
    ├── __main__.py          # main(): argparse --port/--data-dir, Gradio check, build + launch
    ├── jobs.py              # JobStatus, Job, JobStore (lock, atomic jobs.json, recovery), JobBusyError
    ├── submit.py            # LANGUAGES/MASKS mappings, validate + create job files (no Gradio)
    ├── worker.py            # JobWorker: queue + daemon thread → process_audio
    └── app.py               # build_app(store, worker): Blocks layout + event handlers (only Gradio import)

tests/
├── conftest.py              # + slow/failing fake transcribers, words/mask fixtures
├── unit/
│   ├── test_probe_audio.py      # WAV/MP3 duration, bad extension, corrupt file
│   ├── test_preset_preview.py   # length, fades, peak, unknown name
│   ├── test_ui_jobs.py          # transitions, persistence round trip, recovery, corrupt file, delete rules
│   ├── test_ui_submit.py        # every validation message; no job on failure; file copies
│   └── test_ui_worker.py        # FIFO, queued while running, failure isolation, cleanup, one transcriber
└── integration/
    ├── test_ui_parity.py        # CLI main() vs worker: byte-identical WAV + JSON
    └── test_ui_app.py           # build_app() smoke; submit/refresh/select/delete handlers
```

**Structure Decision**: Single package. `bleeper.ui` is a new subpackage beside `bleeper.cli`.
Only `ui/app.py` (and `__main__.py`, lazily) imports Gradio, so `jobs`, `submit` and `worker` are
plain Python that is testable without the web stack. All audio work goes through `bleeper.core`
public names.
